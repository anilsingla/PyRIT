# Report Analysis Guide

This document explains the reports generated by `samples/security-evaluator` and how to interpret them.

## Generated report files

### `reports/scorer_outputs.json`

- Contains detailed scorer payloads for every executed case.
- Includes scenario metadata, dataset labels, prompt/response content, and individual scorer values.
- Best for importing into analysis tools or the PyRIT GUI.

### `reports/scorer_comparison.csv`

- Flattened view of scorer results.
- Ideal for spreadsheet analysis.
- Each row typically includes:
  - OWASP scenario ID
  - dataset name
  - scorer name and score
  - weighted majority and confidence
  - disagreement flag

### `reports/run_report.json`

- A compact manifest of the run.
- Summarizes execution configuration, artifact paths, and per-mode totals.
- Use this file to confirm the exact attack mode, dataset selection, and output folder.

### `reports/baseline_scan_report.json`

- Baseline mode summary results.
- Contains compliance/refusal counts per scenario and dataset.
- Useful for comparing baseline behavior against attack modes.

### `reports/rescore_report.json`

- Output of `--attack-mode rescore`.
- Lists rescored assistant messages from SQLite memory.
- Use to compare scorer behavior after model updates.

### `reports/run_report.html` and `reports/run_report.md`

- Generated HTML and Markdown reports.
- The HTML report is easier to browse and share.
- The Markdown report is useful for version control and text review.

### `reports/cases/`

- Hierarchical per-case output.
- Files are grouped by scenario, dataset, seed group, and scorer.
- Each JSON file contains the full case payload and scoring details.

### `logs/pyrit_owasp_redteam_production.log`

- Runtime and checkpoint log file.
- Contains operational events, errors, and resume checkpoints.
- Useful for debugging failed runs or interrupted executions.

## Understanding the report structure

A typical run folder looks like:

```text
reports/
  redteam/
    datasets__harmbench/
      scorers__self_ask_true_false__refusal/
        20260518T120000Z/
          scorer_comparison.csv
          scorer_outputs.json
          run_report.json
          run_report.html
          reports/
          cases/
```

And the per-case folder layout looks like:

```text
cases/
  LLM01_prompt_injection/
    harmbench/
      group_1/
        self_ask_true_false/
          case_00001_scenario_00000.json
```

## How to analyze the reports

### Quick checks

1. `run_report.json`
   - Confirms mode, dataset selection, and run metadata.
2. `scorer_comparison.csv`
   - Good for high-level filtering and spreadsheet comparisons.
3. `scorer_outputs.json`
   - Use for detailed case-level import into the GUI.
4. `cases/`
   - Inspect single-case JSON files for exact prompt/response flow.

### Score interpretation

Key fields in scorer reports:

- `weighted_majority`
  - Indicates the consensus among scorers.
- `weighted_confidence`
  - Shows how strongly scorers agreed.
- `disagreement`
  - Flags cases where scorers differ.
- `score_value`
  - The actual value assigned by a scorer.

### Comparing modes

Use the same dataset and scorer selection across modes to compare:

- baseline vs redteam
- redteam vs tap
- tap vs crescendo
- xpia vs baseline

Look for changes in:

- refusal rates
- compliance rates
- weighted confidence
- disagreement cases

### Dataset comparison

When using multiple datasets, compare:

- how each dataset affects success/failure rates
- dataset coverage under `RUN_ALL_AVAILABLE_DATASETS`
- whether model behavior changes between datasets

### Expected report outputs by mode

- `baseline` creates `baseline_scan_report.json` plus the usual `scorer_outputs.json` and `scorer_comparison.csv`.
- `redteam`, `tap`, and `crescendo` each create the usual `scorer_outputs.json`, `scorer_comparison.csv`, and `run_report.json`.
- `xpia` creates the usual reports plus `run_report.json` for the injection run.
- `rescore` creates `rescore_report.json` without generating attack artifacts.

## Best analysis workflows

### Option 1: Quick spreadsheet analysis

Open `reports/scorer_comparison.csv` in Excel or LibreOffice.
Filter by:
- OWASP scenario ID
- dataset
- scorer name
- weighted confidence
- disagreement

### Option 2: Import into the GUI

1. Import `reports/scorer_outputs.json` into the PyRIT GUI.
2. Use filters for scenario, dataset, model, and scorer.
3. Compare multi-turn flows and per-case results interactively.

### Option 3: Raw JSON drill-down

Open an individual case file under `reports/cases/`.
This is the best way to see the exact prompt, model response, and scoring payload.
